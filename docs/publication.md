# 公开发布前检查

此目录是独立整理后的源码副本。原始目录中的数据库、备份、日志、个人资料和开发记录没有被删除，也没有被复制到这里。

## 已排除

- `.local/` 中的个人公司分级；公开版本不预设公司优先级。

- SQLite 数据库、备份、锁文件及数据库临时文件。
- `notes/`（包括面试归档）、`reports/`、个人开发上下文和计划。
- `.venv/`、`node_modules/`、缓存、覆盖率文件、构建产物和系统文件。
- 前端旧 `.git/` 历史及 `.openai/` 私有部署元数据。
- 未使用的 Sites 打包插件、认证辅助代码、D1/Drizzle 示例和默认占位图标。

前端原始 Git 历史中曾跟踪私有部署元数据；不要将该历史直接用于新公开仓库。此副本从当前源码文件整理，保留了原始工作区内尚未提交的业务代码。

## 仍需所有者决定

1. 确认有权公开项目代码及保留的公开岗位摘要。`frontend/app/jobs.ts` 是带日期的公开来源快照，没有复制个人投递状态，但并不代表实时招聘状态。
2. 选择许可证后添加 `LICENSE`，确认所选许可适用范围及第三方声明。当前未自动指定作者、版权主体或许可证。
3. 确认默认公司列表、岗位筛选偏好以及快照适合公开；需要时可在首次发布前删减或替换快照。
4. 发布前核对目标 GitHub 仓库、可见性和准备提交的文件。

## 上传时

仅使用此干净副本初始化新仓库。审阅准备提交的文件，特别是新增的 `.env`、数据库、导出文件、日志和部署配置。忽略规则不会移除已经被 Git 跟踪的文件。

```bash
git init -b main
git add .
git diff --cached --stat
git diff --cached --check
git diff --cached
```

以上仅为本地准备命令，不会推送。扫描基于常见凭据、个人信息和路径模式，不能保证识别所有可能的敏感内容。原目录历史未做完整历史凭据审计，也未重写。
